TV Launcher

A big-screen home for a Windows PC.

  • Tauri
  • SvelteKit
  • TypeScript
Built
Sep 2026
Platform
Windows
Role
Design and build
Input
Remote, keyboard or gamepad

Why I made it

Using a PC on a TV is awkward. Every app has its own idea of how to work with a remote, and getting from a show to a game to a song means leaving one app and hunting for the next.

Android TV fixes this with one home screen, so I wanted that on Windows. I kept the launcher small and moved everything that brings in content into add-ons, so the base stays simple and each service plugs in without touching it.

What it does

06
Add-onsEach service describes what it needs and returns rows of plain data. It never draws anything.
07
Themes and backupThemes are data files with colors and a few style choices. Settings can be backed up and restored, with optional encryption.

Design principles

The 10-foot rule

Design for someone sitting about three metres away, holding a remote. Every other choice on this page follows from that.

  • 01Focus is the cursorThere is no mouse, so one item is always clearly focused and the arrow keys, D-pad or gamepad move it the way you press. The focus order is predictable, and a dialog keeps focus until it closes.
  • 02Always show the controlsA hint bar along the bottom lists what each button does on the screen you are on, so nobody has to remember.
  • 03Navigation that gets out of the wayThe left navigation is a slim icon rail that opens out when it has focus, so the content gets the screen.
  • 04Dark, with the artwork behind itA dark interface with the picture of what you are looking at behind it, faded at the edges so there is no seam.
  • 05Type lessText fields open an on-screen keyboard, and services can connect with a code shown on screen, the way TV apps do.

What I learnt

  1. 01Adding sources got easier after I split the launcher into a base and add-ons. A new service is one manifest and one file, and the base never changes.
  2. 02A remote has no mouse, so every screen needs a clear focus order. Dialogs ended up as their own navigation scope, and text fields needed an on-screen keyboard.
  3. 03Anything that touches the network should have a short list of places it may talk to. Add-ons are refused any other host, and plain http.
  4. 04Secrets go in the operating system's credential store, not in a settings file. Themes are data and not CSS, which means a theme from anyone is safe to load.
